# FEVER · 회원 소개와 질문 답변

Next.js App Router / TypeScript / Tailwind / Supabase. 제품 기준은 [PRD v1.1](docs/FEVER_PRD_v1.1.md)이며, 추가 확정 사항은 [Phase 2 정책](docs/PHASE2_DECISIONS.md)입니다.

## 실행

Node.js 24 / npm 11 기준.

```sh
npm ci --cache /tmp/fever-npm-cache
npm run dev
```

3000 포트에서 실행합니다. Supabase 설정이 없으면 홈은 실행되고 가입·로그인은 비활성화되며 보호 경로는 로그인으로 이동합니다. 실제 사용자나 가짜 승인 데이터를 만들지 않습니다.

## Supabase 연결 시 수행

1. `.env.example`을 `.env.local`로 복사하고 URL/publishable key를 설정합니다. service role 키는 사용하지 않습니다.
2. 신규 Supabase 프로젝트에는 `supabase/migrations/202610120001_membership.sql`부터 `202610120008_registration_birthdays.sql`까지 번호순으로 적용합니다. 기존 FEVER 프로젝트에는 001–007이 적용되어 있습니다. 가입 시 생년월일·성별과 홈의 이달의 생일자를 켜려면 `202610120008_registration_birthdays.sql`을 SQL Editor에서 한 번 실행하세요. 기존에 비공개로 저장된 생일은 자동 공개하지 않으며 회원이 새 안내에 동의하고 운세 화면에서 다시 저장한 뒤 표시됩니다.
3. Auth에서 Email provider는 켜고 **Confirm email은 끕니다**. 최신 사용자 결정에 따라 별도 이메일 확인 없이 계정 생성 세션으로 가입정보를 입력합니다. 비밀번호 최소 길이는 8자 이상으로 설정합니다. 기존 미인증 계정은 설정 변경 후에도 로그인에 제한이 있을 수 있으므로 운영자가 Auth 계정 상태를 확인해야 합니다.
4. 가입 확인 이메일을 token hash 방식으로 사용하는 경우 템플릿 링크를 `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=signup`으로 설정합니다. PKCE callback 방식도 제공됩니다. 비밀번호 재설정은 `/forgot-password`에서 요청하고 `/auth/recovery`에서 인증한 뒤 `/account/reset-password`에서 처리합니다.
5. `/terms`, `/privacy`에 기본 안내가 포함되어 있습니다. 계정 생성 단계에서 두 필수 동의 체크박스를 선택합니다. 동의한 문서 버전과 시각을 계정의 본인 신고 동의 정보로 보관하고, 같은 버전이면 프로필 입력 단계에서는 체크박스를 다시 표시하지 않습니다. 과거 계정의 동의 정보가 없거나 문서 버전이 바뀐 경우에만 프로필 단계에서 동의를 받습니다. 동의 메타데이터를 회원 승인이나 관리자 역할 판단에 사용하지 않습니다. 가입 신청에는 문서 버전과 동의 시각이 기록됩니다. 별도 정식 문서를 사용할 경우 `FEVER_*` 변수로 HTTPS URL과 버전을 지정할 수 있습니다. 운영자 연락처·실제 처리 지역 등 추가 고지 사항은 정식 운영 전 보완해야 합니다.
6. 신뢰할 수 있는 운영자 계정으로 사진 포함 가입 신청을 완료한 후 `supabase/bootstrap-super-admin.sql`의 UUID를 실제 계정 UUID로 바꾸고 SQL editor에서 최초 1회 실행합니다. 이미 최고 관리자가 있으면 실패하도록 구성했습니다.
7. 서로 다른 회원·미승인·반려·정지·관리자 계정으로 API/Storage/RLS를 실제 Supabase에서 검증합니다. Confirm email을 끄면 Supabase가 신규 계정을 자동 확인 처리하므로 기존 DB의 인증 상태 검사와 호환됩니다. DB의 `pending_email` 상태명은 하위 호환을 위해 유지하며 UI에서는 프로필 미완료로 표시합니다.

FEVER는 `https://fever-amber.vercel.app`에 배포되어 있습니다. 앱은 Supabase publishable key를 사용하며 데이터 변경은 로그인 세션·RLS·검증된 RPC로 제한됩니다.

## 구현

- 이메일/비밀번호 로그인·계정 생성, 세션 refresh proxy, 인증 callback, 로그아웃.
- 이메일 인증 없이 계정 생성 후 프로필·사진·동의를 제출하는 가입 신청. nickname 대소문자 중복 차단, private 사진 bucket, 5MB 형식 제한 및 서버 파일 signature 검사.
- 관리자 가입 승인·반려·재신청 허용 화면과 RPC. 가입 승인과 역할/감사 기록을 한 트랜잭션에서 처리합니다.
- 회원·관리자·최고 관리자 서버 guard와 DB RLS. 회원이 상태/역할을 직접 변경할 수 없습니다.
- 최초 최고 관리자 설정은 운영자의 DB 작업으로 분리했습니다. 일반 웹 사용자에게 권한 자체 부여 API가 없습니다.

- 프로필: 출생연도·지역·성별(선택)·직업·MBTI·자기소개·사진·관심사를 편집합니다. 닉네임의 둥근 테두리는 남성 파랑·여성 빨강 계열·성별 미공개 중립색으로 표시하고, 바로 아래 작은 표시에는 MBTI를 넣습니다. 닉네임 변경은 관리자 승인 전 기존 이름을 유지합니다.
- 이상형 취향: 분위기·체형·성향·성격의 선택지를 복수 선택하여 저장합니다. 승인된 회원에게 공개하며, 관심 있는 상대 성별 입력은 받지 않습니다.
- 내 스타일: 이상형 취향과 별도로 본인의 분위기·체형·성향·성격을 복수 선택해 저장합니다. 승인된 회원과 관리자가 프로필에서 확인할 수 있습니다.
- 회원 찾기: 승인 회원에게만 최신 가입순 목록과 닉네임·지역·직업·MBTI·나이대·관심사 필터를 제공합니다. 다른 회원의 프로필과 누적 공개 답변을 볼 수 있습니다.
- 회원 카드에 저장된 MBTI와 내 스타일을 표시합니다. 성향·성격 스타일 필터로 찾을 수 있으며, 다른 회원의 자기 스타일이 내 이상형 선택과 겹치면 겹친 항목 수를 보여줍니다. 이 수치는 한쪽 취향의 공통 항목 수이며 상호 매칭 점수가 아닙니다.
- 회원 찾기에서 ‘서로 취향이 통하는 회원’을 선택하면 내 이상형 ↔ 상대 자기 스타일, 상대 이상형 ↔ 내 자기 스타일 양쪽에 공통 항목이 있는 승인 회원만 보여줍니다. 회원 상세에는 양쪽에서 겹치는 항목, 공통 관심사, 둘 다 공개 답변한 질문을 대화 소재로 제시합니다. 자동 추천 점수나 연락 기능은 제공하지 않습니다.
- 질문: `/admin/questions`의 등록 안내에 따라 관리자가 카테고리와 주관식·단일 선택 객관식·밸런스게임 질문을 등록하고 비활성화할 수 있습니다. 같은 카테고리의 질문 최대 50개를 `주관식 | 질문`, `객관식 | 질문 | 선택지1 | 선택지2`, `밸런스 | 질문 | 선택지1 | 선택지2` 형식으로 한 번에 등록할 수도 있습니다. 중복 문구는 다시 실행할 때 건너뜁니다. 회원은 질문당 답변 하나를 저장·수정·삭제합니다. 관리자가 숨긴 답변은 회원이 수정·삭제해도 임의로 다시 공개할 수 없습니다. `/discover`와 질문 상세에서는 공개 답변을 통해 다른 회원의 이야기를 찾습니다.
- 메뉴: 하단에서 홈·회원·대화·MY로 이동합니다. 홈에는 사진이 있는 내 프로필, 오늘의 질문, 내 답변 채우기·대화 발견·회원 찾기·오늘의 운세 네 카드를 순서대로 둡니다. 네 카드는 모바일에서 같은 크기의 2×2 배열이며, 탭 즉시 눌림 효과와 이동 중 표시를 제공합니다. 내 답변 카드에는 활성 질문 대비 답변 수를 보여줍니다. 홈 프로필은 소개 수정으로 연결합니다.
- 운세와 생일자: 가입 시 생년월일을 받고 FEVER가 직접 작성한 별자리 재미 운세를 보여줍니다. 홈 하단에는 이달의 생일자를 닉네임·월·일로 표시합니다. 월·일은 회원 본인만 직접 조회할 수 있는 테이블에 저장하고, 승인 회원에게는 제한된 생일자 목록 RPC로만 공개합니다. 이전 버전에서 비공개로 저장한 월·일은 재저장 전까지 공개하지 않습니다. 월·일은 운세 화면에서 삭제할 수 있습니다. 외부 운세 본문을 크롤링하지 않습니다.
- 오늘의 질문: 승인 회원의 홈에서 한국 날짜에 따라 활성 질문 하나를 순서대로 보여줍니다. 해당 질문에 그날 답변을 저장하면 출석이 자동 기록됩니다. 과거에 같은 질문에 답했더라도 오늘 다시 저장해야 오늘 출석이 됩니다. 하루 한 번만 기록되며 답변을 나중에 삭제해도 그날의 참여 기록은 유지합니다. 최근 다른 회원의 공개 답변이 있으면 ‘오늘의 답변’에 표시합니다. 질문이 아직 없으면 관리자 등록 안내만 표시합니다.
- 벙 참여/대기열은 후속 단계입니다. 관리자가 종료 버튼을 누를 때 참석자 명단 잠금, 신청 순서대로 수동 승격, 무제한 정원은 즉시 확정이라는 정책을 사용자가 확정했습니다.

정지/복구, 역할 변경/마지막 최고 관리자 보호, 탈퇴 및 감사 화면은 후속 단계입니다.

## 검증

```sh
npm run build
npm run lint
npm run typecheck
npm run test:db
npm run test:registration
npm run test:member-features
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

시스템 Chromium이 없으면 `npx playwright install chromium` 후 `npm run test:e2e`를 사용하세요. build/typecheck와 dev/E2E 실행은 순서대로 수행하세요. Next.js가 생성하는 `.next` 타입 파일을 동시에 수정하면 검사에 충돌이 생길 수 있습니다.

`test:db`는 PGlite PostgreSQL 엔진에서 여덟 마이그레이션의 RLS/RPC와 질문·답변·출석 상태 전이, 생일 접근·공개 제한을 검증합니다. Supabase Auth/Storage의 최소 계약 fixture를 사용하며 실제 서비스 통합 테스트를 대신하지 않습니다. `test:registration`은 로컬 Next 서버와 Auth/Storage 응답 fixture로 계정 생성→생년월일·성별 입력→동의→사진 업로드→승인 대기 전환을 검증합니다. `test:member-features`는 모바일 브라우저에서 홈의 생일자, 운세 생일 저장·삭제, 프로필·MBTI·회원 찾기, 질문 답변·대화 발견, 관리자 질문 등록을 fixture 백엔드로 검증합니다. 실제 회원 계정을 만들지 않습니다.

## 관리자 계정 로그인과 비밀번호 복구

최초 관리자 SQL은 대상 계정을 가입 승인하고 최고관리자 역할을 부여합니다. 성공했을 때 넣은 UID의 이메일로 로그인해야 합니다. 비밀번호는 FEVER 가입 시 만든 값을 사용합니다. UID 변경은 로그인 비밀번호를 변경하지 않습니다.

비밀번호를 잊었으면 `/forgot-password`에서 재설정 메일을 요청합니다. Supabase Auth URL Configuration에 Site URL과 `<서비스주소>/auth/recovery`를 등록해야 합니다. PKCE 메일 링크는 요청한 브라우저에서 열어야 합니다. 다른 브라우저에서 사용하는 token hash 방식이 필요하면 Reset Password 이메일 템플릿을 `{{ .SiteURL }}/auth/recovery?token_hash={{ .TokenHash }}&type=recovery`로 설정할 수 있습니다. 확인 코드는 서버에서 검증하고 실패·만료 시 새 메일을 요청하도록 안내합니다. 회원 프로필·승인 상태·역할은 변경하지 않습니다. 로그인 오류는 이메일/비밀번호 불일치, 기존 미인증 계정, 이용 제한 등을 구분하고 서버 로그에는 코드/상태만 기록합니다. 이메일·비밀번호·인증 토큰은 기록하지 않습니다.

## 로그인은 되지만 관리자 화면에 접근하지 못할 때

로그인한 상태에서 `/account/status`를 열면 본인 이메일, UID, 가입 상태, 등록된 역할을 확인할 수 있습니다. 이 페이지는 본인 정보만 조회하며 가입 승인이나 역할을 변경하지 않습니다. `supabase/inspect-membership.sql`은 운영자의 SQL Editor에서 대상 계정의 상태와 최고관리자 존재 여부를 조회하는 용도입니다. 비밀번호 초기화는 승인 상태/역할을 변경하지 않습니다. 다른 UID로 최초 관리자 SQL을 반복 실행하지 말고 먼저 실제 로그인 UID와 등록 상태를 확인하세요.
